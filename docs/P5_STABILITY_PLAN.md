现有源码的主要梯度路径连通：Actor阶段冻结WM/Critic参数但保留输入梯度，每个想象步使用相应预测姿态构造goal，末端critic可反传；没有证据表明应先重写训练器。当前18k学习率约1.97529e-4仍接近初值，这是原日程的结果，不能称为调度错误。

**唯一新假设：保持世界模型和价值学习速度，让Actor变化慢一些，是否能减少已学动作的反复丢失，同时继续提高完整回报？**

P4波动和模型误差支持提出这个问题，但尚未证明Actor学习率过大是根因。更小LR也可能只让学习变慢，必须与正常续训比较。

## 4. 执行端需要做的有限适配

以下是待实施事项，本计划提交没有修改或执行这些算法/脚本。

### 4.1 Actor独立学习率

在`SuperMimic.set_schedule()`使用配置`actor_learning_rate_scale`，默认1.0。对全局轮次i：

- `base_lr = learning_rate * cosine_multiplier(i)`。
- Actor使用`base_lr * actor_learning_rate_scale`；WM/Critic仍使用`base_lr`。
- A显式1.0，B显式0.5；公共`learning_rate`保持0.0002。
- 保留恢复的Adam动量和step；不能只在resume后改一次LR，也不能把公共LR减半。
- 在已有metrics记录实际Actor/WM/Critic三组LR，继续保留原训练计时和误差记录。

### 4.2 两个run和一个源码工作树
