### 4.1 实际曝光足够排除“总体没练到”

|---|---:|---:|---:|

hard在三个阶段的份额分别为12.6165%、11.9226%、12.6185%；每条flip至少进入53634个WM窗口，每条handstand至少26483个。所有639条hard的4286个reset bin均被访问，flip296/296、handstand1082/1082。LAFAN真实25%、WM约25.49%、Actor约25.00%，也没有被名义配额挤掉。

**剩余未知的是关键相位的有效连续窗口、Actor起点及其模型误差，而不是整个动作是否被见过。** Reset bin被访问不等于该bin有足够连续k8训练或良好的模型梯度。下一轮只需在已有正常采样和前向中补这些计数，不需要重跑数据扫描或增加一套测试体系。

### 4.2 巨大raw Critic数值不等于实际loss爆炸

hard路线14501轮raw MSE为3.0226×10²³，同一次实际优化的survival-weighted objective为 **.278488**；约99.9999976%的平方误差来自精确零存活后缀。P10已经保存同一步实际目标，无需再拿区间平均值代替。

这支持现有加权确实隔离了死亡后缀数值污染，不能再把raw巨值直接当成当前翻转失败或15k低分的原因。它也不证明Actor已稳定、所有想象均真实。论文Eq.(3)无这项累计存活权重，加权仍是项目变体；P9的LAFAN原Critic终点更好这一事实保留。

### 4.3 从代码发现一个更具体的建模自由度

当前WM独立输出35维位姿残差与35维速度残差。根高度可按

`z_next = z + .02 * vz + free_dp_z`

变化，垂直速度另行预测；二者没有共同的积分约束。因此模型可能用位置残差获得更好的高度奖励和存活，而对应速度并不支持这一位移。这是一个有物理意义的研究假设，并非论文已公开实现中的确定抄写错误。

对已有轨迹定义20ms端点梯形残差：

`r_z = z_next - z - .01 * (vz_current + vz_next)`。

该量反映模型内部位置/速度的一致程度。MuJoCo每控制步含四个5ms子步，接触冲量会令端点梯形近似不精确；真实r_z不要求严格为零。

#### 证据A：旧父9000的同动作真实预测

P10发布的六个same-action窗口实际来自 **P9 full9000 WM**。六窗真实 |r_z| 均值约.24–.60mm/步，预测约3.74–23.06mm/步。handstand第8步预测高度高于真实 **.23993m**，预测vz却低于真实 **.70643m/s**；到真实17步失败时模型姿态误差1.4413rad，解析终止概率约.00267。这支持父模型有严重局部失配，而且失配已经出现在k8以内。

然而，只把旧预测vz重新积分并非修复：该handstand第8步高度误差从+.23993m减为+.04856m，第17步却从+.07978m变为−.31017m。速度本身也错；任何结构约束必须继续拟合，不能把替换后尚未训练的模型称为改进。

#### 证据B：P10自己的有效想象轨迹中仍有失配

进一步读取P10保存的selected rollouts，实际更新为18846、20761、26303，并非文件块名对应的整千checkpoint。例：20761轮的cartwheel_R_002__A415，起始参考帧56，transition索引20（第21步）：

| 量 | 该transition两端 |
|---|---:|
| 预测高度 | .618761m → .603143m（下降1.562cm） |
| 预测vz | +.584492 → +.557179m/s（两端均向上） |
| 梯形速度对应位移 | 向上1.142cm |
| r_z | **−.027035m** |
| reward前累计存活 S | **.9993248** |

另在26303轮的inj_torso_jump样本，transition索引28的r_z=−.012363m，S=.99999982。因此失配并非全是零存活后的无关后缀，也并非只在P9旧父出现。

**这些样本按区间最高Critic误差及较大目标残差选出，具有选择偏差，没有相同动作的真实未来。它们不能估计发生率，不能直接当作物理预测误差，也不能证明当前27000的所有flip/handstand均因此失败。** 当前27000父WM的固定同动作证据应在下一轮开始时补齐，而不是又训完才找。

### 4.4 已检查但没有证据升级为主要解释的项

- 真实终止比较机器人与参考的重力z分量，允许参考倒立；并非一律要求upright。
- 现有handstand失败窗的heading非奇异度约.994以上，flip180也远离yaw奇异点；不能把这些失败统一归因于heading奇异。
- 未发现确定的四元数左右乘、角速度坐标、reset来源、共享EMA或评分截断错误足以解释全部零成功。
- 控制时刻已保存动作的有限分析不足以证明硬件力矩瓶颈，也不足以证明所有动作必然物理可达；不据此同时改PD或action scale。
- 全库平均WM MSE小、梯度norm不爆炸、显存用得多，都不能证明关键接触状态的可微预测和梯度正确。

| 奖励/物理终止 | 公开8项奖励；高度.25m、参考重力z差.8；完整clip正式评分 | 机器人XML/PD来自固定上游重建，作者完整软件资产未公开 |

| Actor Eq.(2) | reward前存活权重，H32末端bootstrap，自然clip终点 | 解析软终止temperature .05、保留BCE辅助的组合是本地选择 |
| 观测/目标 | 93维本体观测×10历史、K10未来参考、32维tanh latent | 完整goal向量未公开；713维及根XYZ反馈为本地方案 |
| 采样 | 1s bins、50%uniform/40%return-softmax/10%memory | Gmax10、timeout500、EMA细节及额外hard配额不应称作者默认 |
| 并行规模 | 论文环境4096 per GPU；P10扩大两路各8192 | 论文只在环境行明确per GPU，不能把本地所有batch翻倍称为作者双卡原样配置 |
| 训练长度 | 论文Table A.5列320000，余弦250000至.03× | 达到论文成绩的精确迭代未公开；27000/320000不是复现进度，不能据此盲跑满 |

没有证据支持一次把Critic、LR、goal、reward、PD、采样比例和积分方式都改掉。下一轮优先研究已经观察到的高度/速度不一致；若同动作真实模型误差改善而技能没有改善，再根据关键相位数据研究Actor信用分配。若前8步已可靠、主要在9–32步累积旋转/速度误差，后续才考虑WM k16；k16与P8的想象H16是不同变量。

## 七、资源与效率：当前已经不是“仅用60多G”

P10正常训练资源记录显示两训练进程各 **42492MiB**，加其他进程共 **91252MiB≈89.11GiB**，设备总 **97887MiB≈95.59GiB**。因此两路8192已经把96GB卡的容量大量用起来；直接改成两路16384没有当前容量依据。占显存高不等于计算单元利用率高，但也不能把旧60多GB截图当当前状态。

容器实际 `memory.max=128849018880`，即120GiB；一次 `memory.current≈117.70GiB` 包含可回收文件页缓存。宿主约1007GiB总内存不等于容器可用，也不能把117.70与120简单相减就宣布只剩2.3GiB可用。共享只读参考memmap约45.4GiB，下一轮继续共用；在原有正式节点顺手记录cgroup的anon/file/inactive_file即可，不另建监控或容量扫描。

两路正常每更新约6.9s；新9000次约17.4h，是预算估计，不是测速承诺。P10全库评分已有长度排序；最终两路评分耗时约1230s与7006s，资源竞争不同且缺少完整阶段分解，不能据此宣称某种固定加速倍数。发布阶段网络问题曾通过推既有结果解决，并未重评或重训。

代码和结果发布有一处状态滞后：README仍写P10未启动，index.next_stage的部分完成标记不一致，summary.latest_training和observed计数保留早期快照。实际training.json.last、终点正式评价和完成记录明确为27000。此次更新当前入口与新计划索引；历史训练快照不伪造重写，P11发布程序应从实际终点更新当前状态字段。

每路P10已知沿革训练墙钟约106.2h/106.1h，其中包括继承阶段；这不是单路独占GPU-hours，也不是作者从零3h的同硬件对照。效率差距真实存在，但当前先解决可学性和保持，再做专门效率优化。
