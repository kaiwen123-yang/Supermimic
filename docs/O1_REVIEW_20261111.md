## 6. 本次评分与接线审查的结论和边界

静态阅读未发现足以使已发布R或40/40失真的实质接线错误：

- 训练外壳继承官方Runner，真实调用 `self.step()`、WM learner与policy learner；采样频率和更新顺序保持。Actor确实使用93维proprio的10帧历史，motion goal为官方640维，没有错用含相对根位置的WM goal。
- 评测加载同一checkpoint的Actor和normalizer；reward直接来自真实研究环境的step，没有使用世界模型预测奖励代替物理评分。
- 同一有序manifest映射40个起始帧；未来目标在各自clip末帧clamp，没有越界串入下一个clip。
- 每条分母固定 `0.1×(N_i−1)`，总分为40条的算术平均。失败尾段不从分母删除，失败clip不从总体删除，不拼接逐动作最佳checkpoint。
- 根高度误差0.25m与投影重力z误差0.8的硬阈值保留；只去除训练timeout。auto_reset关闭，hard标志先保留，结束后的active永久关闭，部分reset不会继续给该clip加分或推进其他活跃clip。

需要保留三个准确限定：

1. **完整定义是执行N−1个转移且无硬失败。** 研究环境原生 `motion_end` 因step内部参考推进时序通常在第N次step才触发；O1在原参考完整物理持续时间N−1步停止累计。因此CSV的 `natural_end` 不等于声称每条都由底层motion_end布尔值触发。
2. **reward与quality的时刻对齐不同。** 上游先对旧参考计算reward/termination，派生位姿还滞后一个物理子步约0.005s；O1额外几何指标使用step返回后刷新状态与下一参考。该行为已记录，不影响原生累计R，但不能直接从quality均值反算奖励。
3. **已有保存支持评测，不是full resume。** 三网络、normalizer、config及计数已保存；优化器、replay、sampler历史、RNG、环境/history完整状态没有保存恢复入口。后续使用O1权重只能明确称warm-start，不能当作无缝完整续训。

本审查没有下载大checkpoint或重放策略，不把源码及已发布记录的核对表述为独立重现实验。现有成绩已足以交付本段，无需为了审查重复全量评分。

### 8.2 官方已经支持packed目录，不需要另写训练loader

研究版MotionLoader接受以下packed格式：

| 文件 | 形状 / 语义 |
|---|---|
| joint_pos.npy | `[N,29]`，按官方FK关节顺序 |
| joint_vel.npy | `[N,29]`，同上 |
| root_pos_w.npy | `[N,3]`，世界根位置 |
| root_quat_w.npy | `[N,4]`，wxyz |
| root_lin_vel_w.npy | `[N,3]`，世界线速度 |
| root_ang_vel_w.npy | `[N,3]`，世界角速度 |
| motion_ends.npy | int64，每条动作累计exclusive末帧边界 |
| joint_names.json | 与官方FK精确一致的名称和顺序 |
| motion_names.json | 可选，建议保留原动作ID名称 |

因此可以沿用O1已经使用的关节映射和root局部角速度转world规则，从现有qpos/qvel分块输出六个数组与clip边界。身体位置/方向/速度全库数组不是该格式的必需项，官方会在需要的参考帧上用FK计算。保持已有50Hz数据；packed loader不根据FPS重新采样。

六个float32字段每帧共71个数，即284字节。BONES参考约 **12.624GiB**；BONES+LAFAN约 **12.741GiB**。这只是参考数据的静态容量，未包含replay、网络、优化器、梯度和想象图。当前packed读取为普通 `np.load` 后搬到训练device，**不是按需GPU窗口或零复制CPU memmap**；不能把13GiB当训练总显存。

官方pack工具会先保留所有NPZ字段再拼接；已有连续数组时，直接分块输出官方packed格式更合适，无需绕回13万NPZ，也无需修改官方loader。是否混入LAFAN、从零还是权重warm-start、预算及全库评分批量留给具体下一阶段方案；本次复核没有启动该阶段。
